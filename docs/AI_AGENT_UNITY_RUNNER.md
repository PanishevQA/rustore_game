# Local Unity runner for the AI agent

This is the bridge between cloud/GitHub coding agents and the real Unity Editor installed on the development Windows PC.

Once configured, an agent pull request can execute:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\agent_check.ps1 -Mode Unity
```

on the local machine, and GitHub Actions returns the logs/artifacts to the pull request.

## Prerequisites on the Windows machine

- Unity Hub
- Unity 6000.3.24f1
- Android Build Support for that editor
- GitHub access to PanishevQA/rustore_game
- enough free disk space for the runner workspace and Unity Library

Python 3.13 and .NET 8 are provisioned by the workflow through GitHub Actions setup actions, so they do not need to be manually pinned for the runner.

## One-time runner registration

1. Open the GitHub repository.
2. Open Settings -> Actions -> Runners.
3. Choose New self-hosted runner.
4. Select Windows and x64.
5. On the development PC, open PowerShell in a dedicated folder such as:

   C:\github-runners\nesbeisya-unity

6. Run the download/configuration commands generated by GitHub on that page. Do not save the registration token in this repository.
7. During configuration, give the runner the custom label:

   unity-agent

8. Use a descriptive runner name, for example:

   nesbeisya-unity

9. Install/start it as a Windows service using the service command shown by the GitHub runner setup, so Unity validation does not depend on an open terminal.
10. In the repository open Settings -> Secrets and variables -> Actions -> Variables and create:

    UNITY_SELF_HOSTED_ENABLED = true

The workflow file is:

.github/workflows/unity-agent-gate.yml

Until the repository variable is exactly true, the Unity job is skipped and cannot block pull requests.

## Verify the bridge

Push a harmless commit to an open agent pull request or reopen/synchronize it.

Expected GitHub Actions job:

unity-agent-gate / unity

Expected command inside the job:

scripts/agent_check.ps1 -Mode Unity

A successful run proves all of the following on the real development machine:

- the pinned Unity editor was found;
- the project compiled;
- EditMode tests passed;
- build scenes could be opened;
- committed prefabs could be loaded;
- missing MonoBehaviour scripts were not found;
- broken serialized object references were not found;
- materials/ScriptableObjects passed the serialized validator.

The job uploads these directories even when validation fails:

- artifacts/agent-check/
- artifacts/release-candidate/

The coding agent should read the job log and the uploaded diagnostics, fix repository-owned errors, push again, and repeat until the gate is green.

## Safety

The self-hosted runner uses its own GitHub Actions workspace. Do not point the runner work directory at the human's active Unity checkout.

AgentProjectValidator is read-only. It opens scenes and prefab contents for inspection but does not save them.

The runner token and any GitHub credentials are machine-local secrets and must never be committed.

To disable remote Unity execution immediately, set:

UNITY_SELF_HOSTED_ENABLED = false

or stop the Windows runner service.
